# Canonical meal-plan document template

Use this semantic template when creating or reformatting a canonical meal plan. Read [native artifact storage and formatting](../../../shared/artifact-formatting.md) first. Render these elements with the destination's native features; the Markdown below describes structure and must not be pasted literally into a Google Doc.

## Document structure

1. Document title using the native title style.
2. A compact metadata table containing plan ID, status, covered dates, last updated, household or serving assumptions, and the exact record identities used.
3. A `Safety and unresolved questions` heading followed by short bullets containing only material constraints, assumptions, or pending checks.
4. A `Weekly plan` heading followed by a native table with day, meal, named canonical recipe link, version used, servings, active time, total time, and planned leftovers. A leftover-only row uses a named link to its source dinner or recipe.
5. A `Dinner details` heading with one subsection per dinner. Use labeled paragraphs or a small native metadata table for timing and servings, a bulleted ingredient list, a numbered instruction list, and short bulleted adaptations, prep-ahead, storage, and leftover notes.
6. A `Grocery and cost summary` heading with native section headings and lists or tables appropriate to the finalized shopper handoff.
7. `Batch prep`, `Leftover plan`, and `Sources` headings when their content is useful. Sources use descriptive named links and keep canonical recipe links distinct from original-source links.

Keep the current plan operationally complete without history. Do not copy complete recipes or preference tables into it when stable named links and bounded context are sufficient.
