# Source discovery

Inventory only configured providers, containers, roots, and authorized pointers. Include the canonical profile explicitly even when outside those roots. An index or previous manifest is a discovery aid, not proof of coverage.

`destination.exclusions` applies only to extra-file checks and preservation in the GitHub destination. It does not remove any configured source root, authorize skipping source reads, or turn a source retrieval miss into a deletion.

- Maintain one run-local inventory keyed by `(provider, container, immutable ID)`, with the strongest documented fallback when IDs are unavailable. Track root/page cursors and visited pointer identities separately. Deduplicate overlapping roots and aliases before fetching content; preserve all relevant path mappings and report conflicting identities.
- Complete each listing's pagination once during the initial pass. Follow pointers within authorized scope; record out-of-scope targets without expanding scope. Skip already visited targets and record actual cycles; a repeated alias or a fully traversed cycle alone is not a coverage gap. Repeated pagination cursors, inaccessible pages, or truncated results may prevent complete enumeration: resolve them or mark the run incomplete, never infer deletion.
- Batch metadata and content reads when the provider supports it. Fetch each included identity once per capture phase, reusing the resulting bytes and hashes within that phase. Daily runs may reuse verified bytes when trustworthy versions match; otherwise read and hash. Weekly runs start with a fresh inventory and read all included bytes independently of the daily cache.
- Preserve original bytes and extensions for YAML, JSON, Markdown, binary, and extensionless files. Never convert text, normalize line endings, or regenerate YAML during capture. For provider-native exports record the chosen representation and source version in the manifest and explain fidelity/history limits in the receipt.
- Classify known sensitive records from the authorized source metadata and user instructions; apply [sensitive-record permission](configuration-and-schema.md#sensitive-record-permission). Do not infer a grant from durable designation or a previous successful backup. Keep denied candidates distinct from confirmed deletions. Remote binary read limits follow [remote byte retrieval](weekly-reconciliation.md#remote-byte-retrieval); source bytes are never a substitute for remote recovery evidence.
- When complete listing is unavailable, use bounded searches scoped to the configured roots and record query coverage. Search results alone do not prove completeness. Report inaccessible or ambiguous candidates and retain their last verified copies.
- Perform the required final inventory/version check separately; deduplication must not suppress this check or the independent remote verification. Retry moving records a bounded number of times, then fail complete publication if coherent capture cannot be established.

Record listing/page calls, content reads, duplicate identities, pointer cycles, retries, and access limits in the receipt. Compare an overlapping-root, paginated fixture before and after changes: inventory identities and hashes must match while redundant initial-phase reads decrease. The issue's named conversations are reported context unless actually available; do not invent observations from them.
