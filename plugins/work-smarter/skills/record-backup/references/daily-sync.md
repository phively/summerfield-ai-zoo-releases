# Daily and manual sync

Use this procedure for the scheduled daily run or an explicitly requested manual backup. The manual mode may run immediately with the same profile and lock. A subset is allowed only when the user names it; mark the receipt incomplete for omitted scope.

1. Read and validate the current canonical profile and acquire its lock. Check credentials, repository privacy and identity, branch, and the last verified receipt. Load current sensitive-record permissions but defer per-record decisions until eligibility is selected. If the destination is unknown or diverged, stop before writing. When `destination.exclusions` is non-empty, independently pin the current branch commit and complete tree inventory before staging, following [destination preservation evidence](destination-preservation.md).
2. Use [source discovery](source-discovery.md) to finish pagination for every configured candidate boundary, resolve canonical identities and direct canonical-file mentions, and record explicit user designations. Run `scripts/check_source_scope.py` before `scripts/check_permission.py`; only the selected profile/canonical records, directly mentioned files, and user-designated supporting records proceed to permission. An unrelated candidate in the same root or topic is not a permission request or eligible-coverage gap. Compare selected identities and trustworthy versions with the last verified index. A manual subset preserves entries outside the selected subset; omission never becomes a deletion.
3. Read new or changed selected records and construct a deterministic staging tree and `backup-index.json`. Preserve each configured destination directory from the pinned base. If fresh complete inventory confirms that a prior mirror no longer qualifies under the corrected source scope, keep its indexed identity/path/version/hash and exact stored bytes with `selection_status: retained-out-of-scope`; do not reread it, reauthorize it, or count it as current coverage. Add a neutral-reference coverage limit. Do not use this marker for a manual omission, a retrieval miss, or a current permission denial: preserve those prior copies under their existing incomplete/uncertain outcome. Recheck inventory and selected source versions. Retry a moving selected record a bounded number of times; if a required selected record remains unstable or inaccessible, fail the complete publication and preserve the prior verified snapshot.
4. Run `scripts/validate_snapshot.py` against the staged tree. Pass the current profile-bound destination policy and independent expectations when exclusions exist. Run `scripts/check_destination_preservation.py` separately and require `staged_preserved`. These checks do not contact a provider or GitHub. Review their outputs, counts, and hashes.
5. Reread the branch head immediately before publishing. Use a compare-and-swap or equivalent concurrency check. If a competing commit appears, discard the stale stage, refetch the new base, reapply only intended managed changes, and rerun both checks. Never force-push or merge an obsolete excluded subtree over the new base.
6. Independently read the remote commit and full tree. Confirm branch reachability, manifest equality, all changed/new file hashes, expected removals, and repository path mappings. With exclusions, add the content readback to the preservation packet and require `content_preserved`. For blocked binary reads use the [remote byte retrieval procedure](weekly-reconciliation.md#remote-byte-retrieval), retaining daily scope. Resolve a lost response by reading remote state before retrying.
7. After independent content readback, follow [receipts and reporting](receipts-and-reporting.md) to derive notices from the prior verified identity set, the verified current manifest, selected records, and their successful permission results. Add nonempty `personal_data_additions` and returned coverage limits to the stable pending receipt before refreshing the README. With no source changes, do not create an empty content commit; verify the remote snapshot and report `verified-no-change`, then publish the receipt and README in an operational commit. After independent operational readback, require full `preserved` status when exclusions exist. Keep the profile lock until reporting finishes or is durably queued.

Daily Git captures normally preserve the latest observed state for each day, not every intraday provider revision. Report that history limit accurately. Do not call a source-complete run a complete version-history archive unless the provider proves that coverage.
