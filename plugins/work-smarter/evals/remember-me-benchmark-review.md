**Decision:** Keep the current Remember Me thresholds and index representation pending valid behavioral evidence.

The plan's four-way comparison asks whether the current detailed index with full reads, a compact index with full reads, heading navigation over the detailed index, or heading navigation over the compact index best preserves recall at lower total cost. That comparison requires fresh model sessions, verifiable tool traces and independent final-state evidence. No strict comparison was run: this host's Codex CLI exposes one-shot command execution that the available configuration cannot disable. A trial agent could therefore read controller/gold files. Running the comparison here would violate the isolation contract and make its results untrustworthy.

In that original blocked study, no trial sessions started, no final holdout was defined or exposed, and no baseline or candidate performance results existed. Recall, token usage, latency, amortized cost and uncertainty are therefore unavailable, not zero. No candidate was selected. The deterministic trial builder supplies the assigned full-read or heading-navigation strategy to each public packet, but no model session used them in that blocked study. The adapter includes a controller-authorized synthetic save with version advancement, readback and candidate-reported protected-inventory evidence. Deterministic controls verify that path, including separate-process state and trace reload, but they provide no model or live-provider performance evidence.

Two Cloud capability-probe tasks used separate checkouts. Their inspected trees contained the candidate skill but no benchmark protocol, adapter, scorer, controller or gold paths. A third task in `superb-skills-eval` found a generic comparison script, controller and scorer, but no Issue 24 protocol, target fixtures, gold or holdout inputs, or test files; it ran zero tests. Its response reported GPT-5.6 Sol and no reasoning-effort value despite CLI config overrides requesting GPT-6 Luna High. A Cloud lookup for the current `summerfield-ai-zoo` repository returned 403 (`repo_not_accessible`), so these tasks could not access the target harness. No behavioral trial or U2/U6 scoring occurred. The [probe record](../../../benchmarks/evidence/remember-me/remember-me-20261019-cloud-isolation-probe.json) retains task IDs and limits.

OpenAI documentation says each Cloud task receives an isolated workspace ([Cloud environment docs](https://learn.chatgpt.com/docs/environments/cloud-environments)). YOLO bypasses Codex's inner approvals and sandbox ([CLI reference](https://learn.chatgpt.com/docs/cli/reference)); it does not switch the task to the local checkout, but it gives the agent unrestricted reach within the files and services available to that task. YOLO was not enabled in these probes, and the observed paths do not prove the Cloud VM isolation guarantee.

The structural calibration is limited to the pinned read-only snapshot recorded in the benchmark manifest: source snapshot identifier `ce276b13c47061347080168d7a87583e8d3d633f` in the separate `phively/personal-context` repository, index blob `72c992d7c979cc8d478cfa277df70ea630d935e5`, 40,505 UTF-8 bytes, with 18 Markdown headings. No record payload or personal facts were retained. The synthetic corpus is not a substitute for a measured user workload.

Because the measured decision is unavailable, this work does not change audit thresholds, compaction, or index layout. In particular, it does not conclude that the current detail is efficient, that heading navigation works in the live runtime, or that a compact index would preserve recall. Reconsider those choices only after an isolated pilot can capture actual operations, exit statuses and retrievable artifacts, and after the compliant and deliberately failing controls pass the Superb Skills evaluation gates.

## Authorized development pilot: 2026-10-19

KTD13/U8 permits a development result under explicitly relaxed runtime requirements. Cloud model selection was no longer a blocker, but the Cloud checkouts still lacked the target harness. The local CLI had the complete synthetic harness. Its read-only attempt failed when the adapter tried to persist evidence receipts. Full Access with a procedural restriction to the public packet and adapter then permitted execution. Served-model metadata remains unverified despite an explicit request for `gpt-6-luna` with High effort. Actual whole-turn token counts were available from retained CLI events.

The first Full Access attempt exposed a runner defect: parallel adapter processes loaded the same trace length and issued duplicate receipt sequences. A regression reproduced the race. The tool wrapper now locks before loading adapter state and holds that lock through persistence. That invalid attempt remains retained and excluded from the frozen comparison. ## Bounded descriptive closeout panel: 2026-10-20

The user-approved U2 scope ran 16 retrieval observations and four paid two-turn maintenance sequences against exposed synthetic records. Retrieval coverage was one observation for each A/B/C/D treatment under `index-8k`, `index-40k`, `index-64k`, and `topic-64k`. Each treatment used the same candidate definition recorded in the frozen panel: detailed/full, compact/full, detailed/headings, or compact/headings. Each workload-treatment cell has one sample; the comparisons are descriptive, not a statistical screen.

All 16 retrieval answers failed the corrected scorer, although each assigned read treatment passed its trace-order gate. The scorer reports missing facts or field mismatches per answer; recurring gaps were source attribution, uncertainty, and a smaller number of omitted or mismatched facts. Charged read bytes ranged from 8,186 to 211,181, reported whole-turn token totals from 87,748 to 246,500, and elapsed time from 17.49 to 56.05 seconds. These are synthetic task observations under an exposed Full Access process; they do not show live Library behavior or establish a preferred policy. The first three 8 KiB answers were scored again offline after a defect was found in the original scorer's assumption that public responses contain controller-only fact IDs. Their answers and traces were unchanged, and the corrected scorer still records failures. The frozen runner prompt also requested those hidden IDs for fact answers and protected-inventory entries. The current runner asks for candidate-chosen fact labels and protected-inventory items matched by public authority and anchor; the scorer does not require hidden IDs. These contract corrections did not change any frozen prompt or result.

All four maintenance sequences failed. Each retained an unauthorized synthetic save attempt and no readable staged compaction candidate, so no candidate was approved or promoted and no successful compaction cost was measured. Sequence A's first-turn behavioral failure remains in its original `result.json`. Its continuation had not started because Codex CLI rejected the unsupported `-s` resume flag. Under a separately frozen amendment, the runner resumed that exact session once using the persisted controller prompt; the recovered turn completed, but it could not erase the original failure or produce a candidate. The original result's SHA-256 remains in the evidence record. The panel used 24 planned starts plus this one infrastructure-only recovery, 25 of 26 total starts; one process start and one recovery allowance remain unused. No behavioral attempt was repeated.

Maintenance A's complete elapsed duration is unavailable because the recovery runner did not persist the recovered-turn duration. Its original attempt duration remains in the preserved output, and no estimate is substituted. Token usage is based on retained CLI `turn.completed` events; cached input remains a subset of input. The four maintenance attempts report totals from 210,078 to 464,741 tokens and charged read bytes from 19,013 to 128,136.
